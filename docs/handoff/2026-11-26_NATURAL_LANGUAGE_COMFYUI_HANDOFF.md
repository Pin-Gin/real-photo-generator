## 1. プロジェクト目標

### 第一次目標（現在の開発の中心）

- ユーザーが日本語の自然文を入力し、人物Master・衣装・背景・ポーズ・構図・画風などの参照画像をそれぞれの専用枠に追加する。
- アプリが文章を解釈して**既存の検証済みComfyUIワークフローを複製**し、制御に必要なノード入力や参照画像リンクを変更して**API用Prompt JSON**を生成する。
- 生成前の解釈結果、変更差分、モデル固有の制約を確認できる。実行後は画像、設定、元の日本語、実行JSON、QA結果を紐付けて保存する。
- **当面は成人の架空CG女性キャラクターによるSFWの衣装・ポーズ・カメラ・背景変更を中心に検証**する。
- ユーザーの原文にない人物設定、衣装、構図を勝手に追加しない。

### 最終目標

- ChatGPT画像生成に匹敵する品質、指示追従性、同一人物性、衣装の物理的な着用自然性、複数参照画像の整合性を目指す。
- 達成は**未確認**。高解像度化・シャープ化のみで同品質に達したとは評価しない。
- 将来的な動画生成は既存要件どおり残す（Master＋動作指示、入力画像からのImage-to-Video、最終出力60FPSは**目標**）。静止画アプリで実装済みという意味ではない。

## 4. 必要な制御モジュール

| 論理コンポーネント | 文章指定 | 画像指定 | 主な検証点 |
| --- | --- | --- | --- |
| 人物・同一性 | 顔、髪、体型を保つ | 人物Master | 他人化、顔・体格の変化 |
| 肌色・肌質 | 色白、色温度、微細質感 | 肌質参考 | 不自然な色むら・のっぺり感 |
| 服装 | 品目、色、着方、素材、装飾 | **衣装参考画像の専用枠** | 本当に着用しているか、残留・貼り付け感 |
| 背景 | 自室、ジム、ユニットバス等 | **背景参考画像の専用枠** | 空間構造・接地・遠近感 |
| ポーズ | 座る、立つ、腕の動き | 姿勢参考画像 | 関節破綻、布の追従 |
| アングル | 正面、斜め後ろ、俯瞰 | アングル参考画像 | 撮影方向、視点整合性 |
| カメラ | 高さ、距離、画角、レンズ、被写界深度、縦横比 | 構図参考画像 | 画角、被写体比率、パース |
| 表情・視線 | 笑顔、視線など | 表情参考画像 | 表情だけ変化するか |
| ライティング | 朝光、室内光、逆光など | 照明参考画像 | 人物・背景・衣服の光整合 |
| レンダリング | セミリアルCG、フォトリアルCG、素材・髪・肌 | **品質参照画像の専用枠** | アニメ化・人形肌・ノイズ |
| ネガティブ | `ネガティブ：` 以下の原文 | 原則テキスト | 実効性、副作用、モデル依存性 |

**重要:** これらはアプリ側の制御モジュールであり、同名の単独ComfyUIノードが存在するという意味ではない。モデルに応じて使用するノード群が変わる。未導入ノードが必要なら事前調査と追加承認を行う。

## 5. Webアプリの処理アーキテクチャ（設計案）

```text
ブラウザUI（主文、negative、Master画像、衣装/背景/ポーズ/画風画像）
  -> 原文保全 + 自然文パーサ
  -> 構造化Intent JSON（推定と確定を区別）
  -> モデル／検証済みWorkflowテンプレート選択
  -> 制御アダプター（肌色・服装・背景・姿勢・アングル・カメラ・画風など）
  -> APIワークフローJSON生成（テンプレート複製・ノード入力の書換・接続）
  -> 検証・diff表示・確認
  -> ComfyUI REST API（/upload/image, /prompt, /history, /view）
  -> 生成結果・実行JSON・QA・再現用設定を保存
```

必須の設計原則：

1. 原文を**そのまま保存**し、モデル向けに補う文章・構造化意図・最終送信JSONとは別データにする。ユーザーの否定条件も消さない。
2. **ベースワークフローをバージョンで固定**する。先頭の履歴を適当に採用しない。ノードID、用途、APIスキーマ、モデル、Seed/Steps/CFG、入力画像の役割を検査する。
3. ユーザーが指定していない値は、勝手な創作で埋めず、テンプレート値の維持または「未指定」を採用する。
4. JSON差分を示してから実行し、実行後は元の成功条件を壊さない。
5. UI用ComfyUI Workflow JSONと、`POST /prompt` に渡すAPI用Prompt JSONを区別する。
6. ネガティブは保存・分離しても、**実際に効くとは限らない**。例：Lightning 4steps / CFG 1.0の通常negative条件。モデルごとに「対応」「限定」「未対応」を区別して警告する。
7. モデルやノードの候補は `GET /models/<category>` と `GET /object_info` で確認する。履歴・実行可能性の確認は別。
8. 出力後にMasterと比較し、**同一人物性・衣装物理整合・品質・構図**を独立判定する。
9. **PowerShellは物理的に必ず1行**。ユーザー環境では複数行の貼り付けが逆順になる。Python `-c` 連携の引用符崩れにも注意。

## 6. 次のSFW画像検証（最優先）

### テスト入力

- **人物:** 従来のショートライトブラウンボブの成人架空CG女性Master候補。正式承認済み最新版のパスとWorkflowは**現時点で未確定**。
- **衣装画像:** 2026-11-26に提示された透明マネキン着用の衣装。白いレース／リボンのニットトップス、オーバーサイズの白いケーブルニットカーディガン、ブラウン系チェックのプリーツミニスカート、ハート型バックル・チェーン類。
- 透明マネキン自体の体型・透明素材・背景は人物に転写しない。
- 画像はチャット添付に存在するが、**ローカルでの配置・アップロード先は未確認**。Gitへ画像データをコミットしない。

### テスト順序

| 試験 | 入力変化 | PASS条件 | FAIL例 |
| --- | --- | --- | --- |
| **TEST 01 衣装適用** | 同一人物・同ポーズで衣装画像のみ適用 | 装飾や重なりの再現、自然な布の厚み・体への着用 | 衣装画像を貼っただけ、袖や襟の不整合 |
| **TEST 02 ポーズ制御** | TEST01の衣装を維持し姿勢を1条件だけ変更 | 布のしわ・袖・裾が関節に追従、人物維持 | 腕の動きに袖が追従しない、脚との接触破綻 |
| **TEST 03 アングル・カメラ** | 人物・衣装を維持して方向、高さ、画角を変更 | 体積と衣装構造が自然 | 参照未掲載の背面を「正確復元」と誤評価 |
| **TEST 04 複合** | 衣装・ポーズ・背景・光・カメラ・ネガティブ | 個別条件を満たし大きな人物逸脱なし | アニメ化、人物/衣装/背景混同 |
| **NEG A/B** | 固定条件でnegativeだけ有無・語句を変更 | 効果と副作用を区別して記録 | 何も変えずに「有効」と断定 |

**採否:** PASS／WARN／FAILを画像と設定を照合してユーザーが最終確定。実際の生成に成功するまでTEST01をPASS扱いしない。**まずTEST01だけ**を行い、成功した場合のみ次のポーズ検証へ進む。
